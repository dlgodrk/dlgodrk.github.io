## 3. 배포 뒤 반복할 일

- 페이지를 새로 만들거나 내용을 바꿔 배포했을 때만 `node scripts/indexnow.mjs` 를 실행합니다. `npm run build` 가 만든 `.indexnow-urls.json` 의 URL을 보내며, 키 파일이 사이트에 올라가 있어야 제출됩니다. 바뀐 것이 없는데 반복해서 보내지 않습니다.
- sitemap 의 `lastmod` 는 빌드 환경 변수 `CONTENT_UPDATED_AT` 이 있으면 그 값, 없으면 `src/lib/site.ts` 의 `RULES_CHECKED_AT` 입니다. 매일 00:05(KST) 재빌드는 이 날짜를 바꾸지 않으므로, 내용을 크게 고쳤다면 이 값을 갱신해야 검색엔진이 변경을 알아챕니다.
- 새 계산기 본 페이지는 구글 서치 콘솔의 URL 검사에서 색인 생성을 요청합니다. 하루 요청 수에 제한이 있으니 본 페이지 위주로 보냅니다. 네이버 서치어드바이저의 웹 페이지 수집 요청도 같은 기준으로 씁니다.
- 주 1회: 서치 콘솔의 페이지 색인 보고서(제외 사유), 서치어드바이저의 수집 현황, 검색어별 노출·클릭을 봅니다. 노출은 많은데 클릭이 적은 페이지는 title 과 description 을 고칩니다.

## 4. 남은 일

1. **개인 도메인 결정.** AdSense 는 개인 도메인이 있어야 신청할 수 있어서, 지금의 `github.io` 주소로는 광고 수익화를 시작할 수 없습니다. 도메인은 연 1~2만원대입니다. GitHub Pages 에 연결하면 기존 주소는 GitHub 가 새 도메인으로 자동 이동시킵니다. 색인이 많이 쌓인 뒤에 옮기면 검색엔진이 새 주소를 다시 평가하는 동안 유입이 흔들릴 수 있으니 일찍 정하는 편이 낫습니다.
   도메인을 바꾸면 할 일:
   - GitHub Pages 설정에 사용자 지정 도메인을 넣고 DNS 를 연결한 뒤 HTTPS 를 켭니다.
   - `.github/workflows/deploy.yml` 의 `NEXT_PUBLIC_SITE_URL` 을 새 주소로 바꾸고 다시 배포합니다(canonical, sitemap, OG 이미지 주소가 모두 이 값을 씁니다).
   - 구글 서치 콘솔, 네이버 서치어드바이저, Bing 에 새 사이트를 등록·확인하고 sitemap(네이버는 RSS 도)을 다시 제출합니다.
   - `node scripts/indexnow.mjs` 를 다시 실행합니다.
2. **AdSense 신청.** 도메인을 연결한 뒤에 합니다. 개인정보처리방침에는 광고와 쿠키 안내가 이미 들어 있습니다.
3. **커뮤니티 공유.** 아래 5절 초안을 사용자가 직접 확인하고 올립니다.
4. 선택: 다음 웹마스터도구 등록, 네이버 웹 페이지 수집 요청 추가.
