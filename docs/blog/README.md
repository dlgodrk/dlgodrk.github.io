# 셈도장 계산기 네이버 블로그 원고

네이버 블로그에 그대로 붙여 넣을 수 있는 원고 3편과 발행 안내입니다. 원고의 숫자는 모두 사이트 계산 코드(`src/lib/calc/*.ts`)를 실행해 만든 값이라, 같은 조건이면 https://dlgodrk.github.io/ 의 계산기와 1원 단위까지 같습니다. 숫자를 비교하는 문장("가장 길게", "모두 토요일", "4대보험보다 많습니다" 등)도 같은 값으로 만들거나 테스트로 고정해, 데이터가 바뀌면 원고를 다시 만들 때 실패합니다.

| 순서 | 파일 | 연결 페이지 | 추천 발행일 |
|---|---|---|---|
| 1 | `2026-salary-take-home-table.html` | /salary/ | 2026-10-13(화) 오전 |
| 2 | `2027-holidays-leave-tips.html` | /holidays/2027/ | 2026-10-15(목) 오전 |
| 3 | `2027-minimum-wage-monthly-pay.html` | /minimum-wage/ (시급·주휴수당 계산기는 링크 없이 이름만) | 2026-10-20(화) 오전 |

공휴일 글을 두 번째로 올리는 이유: 글 안의 "2026년 12월 28~31일 연차 4일로 10일 쉬기" 팁은 연말 연차 계획을 세우는 10~11월에 가장 쓸모가 있습니다. 최저임금 글은 검색이 몰리는 12~1월 전에 색인되도록 10월 안에 올립니다.

## 올리는 방법

1. **카테고리 만들기 (처음 한 번)**: 블로그 관리의 카테고리 설정에서 `생활 계산기` 카테고리를 만듭니다. 세 글 모두 이 카테고리에 넣습니다.
2. **원고 열기**: HTML 파일을 더블클릭해 Chrome이나 Edge로 엽니다. 맨 위 회색 상자에는 제목·태그·숫자 기준이 적혀 있고, 전체 선택에서 빠지도록 설정되어 있습니다.
3. **제목**: 위 "제목과 태그"의 제목을 복사해 스마트에디터 제목 칸에 붙여 넣습니다.
4. **본문**: 원고 페이지를 한 번 클릭하고 `Ctrl+A` → `Ctrl+C`, 스마트에디터 본문에서 `Ctrl+V`를 누릅니다. 회색 상자 내용이 따라 들어왔다면 지웁니다.
5. **붙여 넣은 뒤 확인할 것**
   - 글마다 있는 표 2개의 테두리와 숫자 오른쪽 정렬이 유지됐는지 봅니다. 스마트에디터가 표 너비나 배경색을 바꾸면 표를 선택해 표 스타일에서 다듬습니다.
   - 소제목이 큰 글씨로 들어왔는지 봅니다. 일반 글씨로 들어왔다면 소제목 줄을 선택해 '소제목' 스타일을 적용합니다.
   - 본문 링크(글마다 1개)가 눌리는지 확인합니다. 링크를 더 넣거나 같은 링크를 반복하지 마세요.
   - 링크가 있는 마지막 문단에 "셈도장 계산기는 제가 직접 만들어 운영하는 무료 계산기 사이트입니다." 문장이 그대로 들어왔는지 확인합니다.
6. **대표 이미지**: 원고에는 이미지가 없습니다. 휴대폰으로 해당 계산기 결과 화면을 캡처해 1장 넣으면 검색 결과 썸네일이 생깁니다. 개인 정보가 보이지 않는 화면을 씁니다.
7. **태그**: 발행 설정의 태그 칸에 위 태그를 넣습니다. 한 번에 붙여 넣어지지 않으면 하나씩 입력하고 Enter를 누릅니다. 태그는 10개 안팎이면 충분합니다.
8. **발행 설정**: 전체 공개, 검색 허용(기본값)을 확인하고 예약 발행으로 아래 시간에 맞춥니다.

### 피해야 할 것

- 같은 원고를 다른 블로그·카페·사이트에 그대로 올리지 않습니다. 똑같은 문서가 여러 곳에 있으면 네이버가 중복 문서로 보고 노출을 줄일 수 있습니다.
- 사이트 링크를 글마다 여러 번 넣거나 광고 문구를 덧붙이지 않습니다. 반복적인 홍보 링크가 많은 글은 노출이 제한될 수 있습니다.
- 사이트를 만든 사람이라는 사실을 숨기지 않습니다. 남이 만든 도구를 소개하듯 쓰지 않고, 링크가 있는 문단의 운영자 밝힘 문장을 지우지 않습니다(`docs/community/README.md` 원칙 1과 같은 규칙). 운영자 혼자 만든 것이 아니라면 `scripts/blog/posts.ts`의 `DISCLOSURE` 문장을 실제와 맞게 고친 뒤 원고를 다시 만듭니다.
- 숫자와 문장을 손으로 고치지 않습니다. 요율이 바뀌거나 고칠 문장이 있으면 `scripts/blog/posts.ts`를 고친 뒤 아래 "숫자 갱신" 순서대로 다시 만듭니다.

## 발행 시간

네이버가 공식적으로 밝힌 "좋은 발행 시간"은 없습니다. 아래는 블로거들이 흔히 쓰는 경험적인 기준이니 참고만 하세요.

- **평일 오전 7~9시**(출근길 모바일 검색) 또는 **점심 11시 30분~13시**에 예약 발행합니다. 저녁 8~10시도 무난합니다.
- **하루 1편 이하, 주 2편 안팎을 꾸준히** 올리는 편이 몰아서 올리는 것보다 낫습니다.
- 시기를 타는 글은 수요가 몰리기 **1~3주 전**에 올립니다. 새 글이 검색 결과에 자리 잡는 데 시간이 걸리기 때문입니다.

## 숫자 갱신 (원고 다시 만들기)

원고는 `scripts/blog/posts.ts`가 사이트 계산 코드를 불러 만들고, `scripts/blog/posts.test.ts`가 HTML을 쓰거나 검사합니다. 사이트 규칙(`src/lib/calc`, `src/lib/rates`)이 바뀐 뒤 프로젝트 루트에서 실행합니다.

```bash
# 검사만 (원고가 최신이 아니면 실패)
npx vitest run -c scripts/blog/vitest.config.ts

# 원고 다시 만들기 (Git Bash)
BLOG_WRITE=1 npx vitest run -c scripts/blog/vitest.config.ts
```

```powershell
# 원고 다시 만들기 (PowerShell)
$env:BLOG_WRITE=1; npx vitest run -c scripts/blog/vitest.config.ts; Remove-Item Env:BLOG_WRITE
```

테스트는 공식 수치(최저임금 월 환산액, 월력요항 공휴일 수, 4대사회보험 모의계산과 맞춘 실수령액)와 원고에 인용한 숫자를 고정해 둡니다. 비교하는 문장도 함께 고정합니다. 연차 일수별로 가장 길게 쉬는 연휴(/holidays/2027/와 같은 `longestByLeave`: 추석, 연차 1~4일에 6·9·10·11일), 2027년 노동절·제헌절 요일과 대체공휴일, 성탄절·신정 요일, 연봉별 세금과 4대보험의 크기, 최저임금 세후 인상액이 작은 이유(요율 인상 몫 월 5,590원)가 그 예입니다. `posts.ts`도 이런 비교가 데이터와 맞지 않으면 원고를 만들지 않고 실패합니다. 규칙이 바뀌어 테스트가 실패하면 새 근거를 확인한 뒤 고정값과 본문 문장을 함께 고칩니다. 테스트는 제목 40자 이하, 본문 1,500~2,500자(표 제외, 공백 포함), 표 1~2개(`border="1"`), 사이트 링크 글마다 1개(반복 없음), 링크 문단의 운영자 밝힘 문장, 느낌표·이모지·해요체 문장 없음도 확인합니다.
